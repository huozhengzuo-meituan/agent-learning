现代 Agent 的职责地图

先按职责看系统，再决定采用哪个 SDK。模型、Harness、工具环境与会话记录可以分别演进。

  1. 用户 / UI
    意图、展示、取消、批准
  2. Run API
    身份、租户、预算、任务状态
  3. Harness + 模型
    选上下文、决策、工具循环
  4. 工具 / 环境
    验证、执行、返回事实
问题主要负责层需要的证据
下一步该查哪个文件？模型决策 + 工具说明请求与返回结果
是否可以读取这个租户？可信程序权限授权判断与过滤
工具真的提交成功了吗？业务系统与收据持久结果或幂等键查询
中途崩溃后怎么恢复？持久事件/检查点与运行时状态重放与副作用协调
回答是否比上一版好？评估系统固定任务集、版本与多次试验

选择路线：学习机制用小型显式循环；需要统一模型/前端接口时看 AI SDK；需要任务状态图和持久执行时评估相应运行时；希望委托环境与长期任务管理时比较托管 Harness。具体选择由数据边界、可观察性、可移植性与成本决定。

资料：session / harness / sandbox 分离的工程案例；AI SDK 官方抽象。参见第 0012、0030、0037 课。
