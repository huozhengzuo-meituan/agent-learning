01 · 模型调用基础 · LESSON 0003

从服务端发起第一次模型调用

读懂从 Node.js 服务端到模型提供商的一次最小请求，并识别凭据、模型选择、超时与结果的归属。

阅读与检查 15–20 分钟动手任务 25 分钟资料核对 2026-09-22

这一课的具体成果

完成一个模型调用函数的配置审查；没有 API Key 也能用本地替身完成输入输出练习。

前置知识：理解 async/await、环境变量和第 0002 课的输入边界。

先把一次请求做完整

第一次调用的目标很小：给模型一段虚构组件文档，让它回答一个具体问题。浏览器把问题发给你的服务端；服务端配置模型提供商并发起请求；结果回来后再决定向浏览器返回什么。你熟悉的请求校验、超时、错误显示仍然适用。

本课选择 AI SDK Core 与 Anthropic 官方适配器作为具体例子。generateText 文档描述一次文本生成；适配器文档说明默认读取 ANTHROPIC_API_KEY 环境变量。学习目标是读懂请求边界，提供商选择不会改变这个能力。

配置留在服务端

不要把 API Key 写进前端源码、公开环境变量或提交到版本库。这里使用进程环境变量，并在调用前检查是否配置。模型标识通过 MODEL_ID 提供，避免把示例里的某个历史型号误当成所有账号都可用的默认值。实际接入时，选择账号支持的型号，并记录所安装依赖与模型配置。

下方片段没有在本工作区安装依赖，也没有调用收费 API。后续你决定做真实调用时，需要自己在服务端环境配置凭据，再安装与你项目锁定版本兼容的 ai 和 @ai-sdk/anthropic。本课的无钥匙路径可以先验证代码组织，不能证明远端模型质量。

返回字符串之前，还要看状态

给请求配置输出上限和取消信号，能够把最小调用的边界显式化。这里关闭自动重试，是为了让初次观察时“一次函数调用”不暗中包含多次网络尝试；第 0011 课再训练重试策略。AI SDK settings列出了这些选项和提供商兼容性说明。

拿到 text 只说明获得了生成文本，不等于内容与文档一致。还要核对完成原因、用量和回答是否遗漏关键条件。不要在日志里打印完整凭据或真实私密文档。本练习只记录“是否有回答”等有限信息；精细追踪在后面单独学习。

把过程放进 TypeScript

官方接口教学片段，未安装依赖、未运行真实 API。运行环境是支持所用 API 的 Node.js 服务端；不要复制到客户端组件。

import { generateText } from "ai";
import { anthropic } from "@ai-sdk/anthropic";

export async function answerQuestion(question: string) {
  const modelId = process.env.MODEL_ID;
  if (!modelId || !process.env.ANTHROPIC_API_KEY) {
    throw new Error("请在服务端配置模型与凭据");
  }

  const result = await generateText({
    model: anthropic(modelId),
    instructions: "只依据给定文档回答；资料不足时说明。",
    prompt: [
      "文档 button-v2：loading=true 时阻止重复点击。",
      "问题：" + question,
    ].join("\n"),
    maxOutputTokens: 300,
    maxRetries: 0,
    abortSignal: AbortSignal.timeout(15_000),
  });

  return {
    text: result.text,
    finishReason: result.finishReason,
    usage: result.usage,
  };
}

这里的 instructions 来自可信服务端配置，question 是待处理的用户输入。超时信号表示请求可被取消，不构成“服务商一定没有发生费用”的保证。真实调用成功后也要检查回答内容，而不是只看 HTTP 成功。

动手：不用 API Key 练习请求边界

  1. 给 answerQuestion 写一个本地替身：返回固定的 text、finishReason 和标记为 mock 的用量；不要将虚构用量当作真实计费数据。
  2. 模拟缺少配置、正常返回、抛出网络错误三个场景，并写出界面应该展示的状态。
  3. 在上方片段标记：哪一处选择模型，哪一处携带用户问题，哪一处限制输出，哪一处控制取消。
验收条件

能够说明 key 由服务端保管；失败不会伪装为正常答案；本地替身明确标 mock；没有真实调用时，报告中不写“API 已验证”。

做过以后，再看参考答案

本地替身可定义为返回 { text: '根据 button-v2，loading=true 会阻止重复点击。', finishReason: 'mock-complete', usage: null }，并给测试路径单独命名。配置缺失属于启动或请求配置错误，网络异常属于请求失败，两者都应显示可理解的失败状态。替身验证接口组织，不能验证鉴权、模型能力或费用。

停下来，从记忆里回答

生产前端需要问模型问题时，提供商 API Key 应由谁持有？

答案与理由

应选“服务端持有”。浏览器向你的服务端发送业务请求；提供商凭据不作为前端公共配置交付。

换个需求，还能用吗？

团队要求换成另一家模型提供商。哪些能力应该保持，哪些配置必须重新核对？

迁移题参考要点

保持请求与错误边界、任务规格、输出验收和敏感信息处理；重新核对适配器、鉴权、模型标识、参数支持范围及输出用量字段。统一 SDK 减少接口差异，但不能保证不同模型具有相同能力。
