03 · 工具与执行循环 · LESSON 0007

为模型设计清晰的工具契约

为“读取一份组件文档”定义模型能理解、程序能验证的工具契约。

阅读与检查 15–20 分钟动手任务 30 分钟资料核对 2026-09-22

这一课的具体成果

写出一个 readComponentDoc 的名称、用途、输入、输出与失败语义，避免把访问权限交给模型参数。

前置知识：完成第 0005 课，能解释运行时校验与业务校验。

工具是一个有边界的接口

工具的名称和描述帮助模型选择动作；输入 schema 约束参数形状；执行函数把动作落实到环境；结果让下一轮知道实际发生了什么。AI SDK 工具文档将这些元素分别表达为 description、inputSchema 和 execute。定义一个工具，并不等于它适合任意任务。

例如“操作组件”范围太宽，而“按已知文档 ID 读取一份组件说明”明确得多。好的接口告诉模型什么时候适用、什么时候不适用、找不到内容如何处理。你可以把它当成给刚加入项目的同事写函数文档，只是调用方会依据自然语言描述来选择函数。

输入尽量表达业务意图

我们的助手需要文档 ID，不需要任意文件路径或 URL。把输入设计成 docId，可以让宿主用自己的映射找到材料，也避免把文件系统位置暴露为调用自由度。组件名与版本是否必须分开，取决于文档存储方式；本课用唯一 ID，让一次调用只指向一份明确材料。

不要让模型填写 apiKey、isAdmin 或 tenantId 来决定权限。这些属于可信运行上下文，由服务端根据当前用户确定。inputSchema 证明的是输入形状，不证明调用者有资格读文档。第 0008 课会把这个区别落实为执行代码。

返回结果要支持下一步判断

成功结果至少包含文档标识、版本和相关正文。失败结果应该区分参数错误、不可访问和不存在等应用需要处理的情形，同时避免泄漏本来不该被看见的资源信息。模型拿到“失败了”四个字，往往难以选择有意义的修复；拿到一个边界明确的错误码会更容易处理。

但不要向模型返回内部堆栈、凭据或整份数据库记录。工具返回什么，也是在决定下一轮看到什么。接口设计不只是“参数凑齐能跑”，还包括结果体积、来源与错误的可行动性。初期只做少量窄工具，更容易在具体任务上判断契约是否足够。

把过程放进 TypeScript

当前 AI SDK 工具定义片段，未安装依赖。这里故意不提供 execute，表示只定义契约；它本身不会读取任何文档。

import { tool } from "ai";
import { z } from "zod";

const readComponentDoc = tool({
  description: [
    "按已知文档 ID 读取一份虚构组件说明。",
    "用于核对组件 API 和版本行为。",
    "只返回当前用户可访问的材料；不搜索未知文档。",
  ].join(" "),
  inputSchema: z.object({
    docId: z.string().min(1).max(80)
      .describe("文档唯一 ID，例如 button-v2"),
  }),
});

type ReadDocResult =
  | { ok: true; docId: string; version: string; text: string }
  | { ok: false; code: "INVALID_INPUT" | "NOT_AVAILABLE" };

NOT_AVAILABLE 在本教学契约里合并“没有这份材料”和“当前不可访问”，避免把资源是否存在作为额外信息暴露出去。内部日志可以记录更精确的原因，但不需要全部发送给模型。

动手：替换一个过度宽泛的工具

  1. 把 doAnything({ command: string, isAdmin: boolean }) 改成只读组件文档的窄接口。
  2. 写两个合法输入、两个非法输入，并说明 schema 能发现什么、不能发现什么。
  3. 写一条 NOT_AVAILABLE 结果后模型可以采取的合理下一步：说明缺资料或使用其他已授权材料，不要绕过权限。
验收条件

输入不包含权限开关或任意 shell 命令；描述明确用途和不适用场景；成功与失败结果能够区分；能解释合法 docId 不等于可访问。

做过以后，再看参考答案

合法输入如 {docId:'button-v2'}、{docId:'dialog-v1'}；非法形状如 docId 为数字或空字符串。一个结构合法但未授权的 ID 仍必须被执行层拒绝。NOT_AVAILABLE 之后可以说明目前无法获得该资料，并询问是否有其他可用来源；不能把更换账号或猜路径当成自动后续动作。

停下来，从记忆里回答

模型提供的 docId 通过 schema 校验，下一步还需要什么？

答案与理由

应选“检查访问权限”。服务端可信上下文决定允许访问哪些文档；模型不能通过填写字段自行获得权限。

换个需求，还能用吗？

同样的助手需要“搜索文档”能力。为什么不直接把 readComponentDoc 的 docId 改成任意 query 就算完成？

迁移题参考要点

搜索与按 ID 读取有不同语义：搜索需要查询文本、结果数上限、排序与候选摘要；读取需要明确文档标识及版本。可以新增一个窄搜索工具，让返回的 ID 进入后续读取流程，而不是让一个参数同时表示两种动作。
