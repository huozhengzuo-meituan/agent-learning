01 · 模型调用基础 · LESSON 0002

一次模型调用究竟看到了什么

根据一次调用的输入清单，判断模型知道什么、不知道什么，并为输出预留上下文空间。

阅读与检查 15–20 分钟动手任务 20 分钟资料核对 2026-09-22

这一课的具体成果

为 Button 文档问答写出一张“本轮可见信息表”，指出缺失信息与不应进入提示的服务端信息。

前置知识：完成第 0001 课，理解模型请求与工具结果的区别。

每一次调用都有输入边界

把模型调用看成一个远程函数：它处理这一次请求携带的输入，以及服务提供者明确管理的上下文。你本地打开了哪个编辑器、数据库里有哪些文档，不会因为这些东西“存在”就自动进入模型视野。使用服务端会话或托管 Agent 时，部分历史可能由服务维护；应用仍应确认本轮实际采用了什么，而不是假定永久记忆。

一个常见错误是第一轮给了 Button v2 文档，第二轮只发送“再解释一下”，却期待模型一定知道“再”指什么。无状态调用需要应用传入必要历史；有状态接口需要正确关联会话。前端聊天窗口展示的完整记录，与本轮发送给模型的记录，也可能并不相同。

上下文是工作材料，不是无限仓库

本课把模型本轮处理的指令、消息、文档片段和工具结果统称为模型上下文。Anthropic 的上下文工程文章讨论了如何在有限空间里选择高价值信息。我们的工程任务是为当前问题选择足够的材料，并保持来源与版本清晰；不是把所有资料简单拼接。

例如用户问 v2 的 loading 行为，加入 v1、v2、v3 三份互相冲突的说明而不标版本，会让任务更难。只提供 v2 的相关段落，再记录没有查到的边界，通常更容易检验。第 0014 课会讨论系统化选择方法，这一课先练习发现遗漏与歧义。

Token 影响容量、费用与截断

Token 是模型处理文本等输入时使用的单位，不等于一个汉字、一个英文单词或 JavaScript 字符串长度。不同模型的分词方式和多模态计量方式可能不同。不能用 text.length 假装得到准确 token 数；实践中使用服务提供的计数工具或调用结果里的 usage，并区分估算值与实测值。

做预算时同时考虑输入与可能产生的输出，还要看具体模型对上下文、输出和推理 token 的限制。下面的算术只训练容量意识，不是供应商计费公式。即使材料放得下，也不意味着模型一定正确使用了每个细节；容量测试与答案质量测试要分别做。

把过程放进 TypeScript

下面是自定义输入清单与预算算例，不是实际 tokenizer。所有 token 数字都是题目给定的假设。

const visible = {
  instructions: "根据提供的文档回答，缺少信息时说明。",
  question: "Button v2 的 loading 会阻止点击吗？",
  documents: [{
    id: "button-v2",
    text: "loading 为 true 时阻止重复点击。",
  }],
};

const exampleBudget = {
  contextCapacity: 8_000,
  reservedOutput: 1_000,
  instructionsAndHistory: 1_200,
  toolDefinitions: 500,
};

const maxDocumentBudget =
  exampleBudget.contextCapacity -
  exampleBudget.reservedOutput -
  exampleBudget.instructionsAndHistory -
  exampleBudget.toolDefinitions; // 5_300

5,300 只是当前假设下留给文档的预算。实际调用还应遵守提供商约束、序列化开销和计数方式。用户身份凭据用于宿主鉴权，不应为了“上下文完整”直接塞入 visible。

动手：做一次上下文审计

  1. 列出指令、用户问题、Button v2 文档、之前的聊天消息、API Key 五项材料。
  2. 分别标记“本轮需要发送 / 当前不需要发送 / 仅宿主使用”，并给出理由。
  3. 把问题改成“v1 升级 v2 有什么变化”，指出当前输入缺什么，不要凭空补写 v1 行为。
验收条件

API Key 不在模型可见材料里；升级问题明确需要 v1 证据；你能解释聊天界面显示过某条消息为何不等于本轮必然发送了它。

做过以后，再看参考答案

当前问答需要任务指令、明确版本的问题和 v2 相关文档；无关聊天不必发送，必要的指代历史才加入。API Key 仅用于宿主与服务的认证。改为版本比较后，应取得 v1 对应文档，或说明缺少 v1，不能以 v2 说明推导 v1 的历史行为。

停下来，从记忆里回答

本地存在但没有随请求或工具结果提供的文档，应怎样看待？

答案与理由

应选“默认尚不可见”。本地文件、前端显示状态和模型实际输入是不同对象；托管会话也应按接口规则确认可见内容。

换个需求，还能用吗？

用户新开一个会话，问“按我上次那个项目的规范来”。你该检查哪两件事？

迁移题参考要点

首先确认“上次项目”是否有明确标识与可授权访问的记录；其次确认相关规范是否进入当前上下文。不能依靠跨会话自动记忆的假设。如果不知道项目，应该澄清；如果知道但没有规范，需要检索。
