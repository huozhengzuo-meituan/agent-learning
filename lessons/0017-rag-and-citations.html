06 · 知识与记忆 · Lesson 0017

让回答与检索证据对应

把事实性断言映射到实际读取过的证据，并区分“引用存在”与“证据足以支持”。

阅读与判断 15–20 分钟实验 20–40 分钟资料核对：2026-09-22

前置：第 0015–0016 课；结构化输出与运行时校验。

能力状态：引用与支持性分层是通用设计；Claude citations 是特定提供商能力。示例为未接 API 的概念代码。

本课服务于研发知识助手项目；页面备齐不代表已经掌握。以动手结果、解释和后续迁移作为学习证据。

带着引用也可能答错

知识助手回答：“所有项目均已升级至 2.3［文档 A］。”文档 A 实际只写“Atlas 项目计划在下周升级”。链接是真的，结论仍是错的。要分别检查来源存在、模型本次可用、断言得到支持、适用范围一致。厂商的引用能力可以给出文档位置，例如 Claude 的 citations 支持结构化定位；它不能替你判定原始资料是否正确或已过期。资料：Citations。

Agentic retrieval 中，search 命中一个标题不等于 read 读到了证据。把真正读取并授权的片段存到本次 evidence map，再允许模型输出这些 ID。工具结果应包含 title、位置、版本、取回时间和原文片段。用户打开引用时，仍要执行访问检查。

先做机器可判定的检查

下面是最小结构检查：事实断言必须关联当前证据集合中的 ID。它只能挡住凭空生成的编号，不能判断“计划”是否被误读成“完成”。JSON 本身仍需先按第 0005 课的方式验证，TypeScript 类型不会自动校验模型返回的字符串。

type Claim = { text: string; evidenceIds: string[] };
type Evidence = { id: string; text: string; version: string };
function validateCitations(claims: Claim[], evidence: Evidence[]) {
  const allowed = new Set(evidence.map(e => e.id));
  return claims.map(claim => ({
    text: claim.text,
    validReferences: claim.evidenceIds.length > 0 &&
      claim.evidenceIds.every(id => allowed.has(id))
  }));
}
// validReferences=true 仅说明引用 ID 合法，不能输出 grounded=true。

再检查含义与证据缺口

对重要断言单独比对主体、时间、条件和否定词。可让模型评分器辅助标记“支持／矛盾／信息不足”，再抽样人工校准；关键业务字段尽量做确定性核对。Agent 评估文章把研究型任务的支持性、覆盖度和来源质量分开讨论。资料：Research agent evals。

有了“信息不足”分支，Agent 可以针对缺口继续检索。例如文档证明“Atlas 已升级”，却无法证明“所有项目”，下一次搜索应寻找全量项目清单及状态。预算耗尽时缩小结论或说明未知，不把工具调用失败变成“没有相关资料”。

可读的交付：“Atlas 已升级至 2.3［发布记录 §2，版本 r8］；其他项目状态暂未核实。”把观察、推断和未知分别写清楚，引用紧挨它支持的断言。

动手：让边界可观察

  1. 证据 E1：“Atlas 已升级 2.3。”E2：“Boreal 计划升级 2.3。”为“两个项目均已升级”创建一个 Claim。
  2. 先运行 ID 检查，再人工检查语义。将 E2 改成 E9 观察两类失败的不同。
  3. 改写为两条有独立证据的断言，并写出还需要什么证据才能确认 Boreal 完成。

验收：你能展示一个“引用合法但结论不支持”的例子；修正后的回答保留“计划”语义，不把未来时态改成完成时态。

建议先独立完成；本课代码用于理解机制。实验可在工作区新建笔记或 TypeScript 文件，真实 API 与依赖准备见 实验说明。

完成后查看参考解

原 Claim 引用 E1、E2 时编号检查通过，语义检查应失败或标记信息不足，因为 E2 只给出计划。换成 E9 后编号检查直接失败。参考回答：“Atlas 已升级至 2.3［E1］；Boreal 的记录目前仅说明升级计划［E2］。尚需实际发布结果或部署版本读回确认。”

这里的读回结果是对环境状态的观察；模型写出“已完成”的一句话本身不能成为新证据。

答案与理由（无脚本时也可查看）

答案：编号属于已读集合。编号检查只说明引用集合正确。语义支持、来源可信度、版本适用性都需要独立判断。

迁移题参考思路

把 not_found、forbidden、timeout 明确建模为不同结果，禁止将失败当空结果。答案应说明无法访问，不能声称文档不存在。评估集增加工具报错与真实空集的对照案例。
