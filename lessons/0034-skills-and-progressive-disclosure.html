Skills 与渐进式上下文加载

把一项领域方法封装成 Skill，并验证按需加载的触发与边界。

阅读 10–15 分钟 · 练习 20–40 分钟来源核对：2026-09-22应用侧 · TypeScript

本课交付：把一项领域方法封装成 Skill，并验证按需加载的触发与边界。

前置：0014 选择下一步真正需要的上下文、0018 记忆的写入、读取与失效、0027 识别提示注入与信任边界、0031 长任务的计划与运行支撑

场景统一使用虚构文档与工单。代码注明示意时，需要接入你自己的项目上下文；本页不会发起模型调用。

先理解这个工程问题

Skills 把可复用的方法、参考资料和脚本组织成可发现的包。例如“根据版本化文档生成发布差异”是一套领域做法，不需要每次把全部指南塞进系统提示。模型参数不因安装 Skill 而改变，它在运行时获得的是新的上下文与可调用资源。

Agent Skills 开放规范描述 SKILL.md 的元数据与正文，以及 scripts、references、assets 等目录。渐进加载先暴露名称和描述，匹配任务时读取正文，只有需要时才打开具体参考。这样可以降低无关内容对上下文的挤占；能否正确触发仍要评估。

描述要包含适用任务和边界。只写“帮助处理文档”会过于宽泛；本课练习写成“比较两个指定发布版本，输出每项变更的来源与未确认差异；不执行发布”。这份方法应指导行动，却不自动增加写入权限。受信任的安装来源、版本固定、脚本审查与运行隔离仍由宿主负责。

具体失败：助手被问“介绍发布流程”时加载了自动发布 Skill，并尝试执行脚本。需要同时修复过宽触发描述和权限门禁。官方接入指南讨论如何把 Skills 集成进客户端；每个产品的启用方式与扩展字段可能不同，规范文件存在不代表你的运行时已经支持全部行为。

读一段代码或执行轨迹

先预测输出或指出边界，再对照注释。以下为课程教学片段；基础机制的可运行实验见 实验说明。本课特定集成需按练习自行实现，未声称已运行。

// 目录内容示意；name/description 放在 SKILL.md 的 YAML frontmatter。
release-diff/
  SKILL.md
  references/
    evidence-rules.md
  scripts/
    compare.ts

// SKILL.md 示例（不是 TypeScript 代码）
---
name: release-diff
description: 比较两个指定发布版本，输出变更证据与缺口；不执行发布。
---
1. 确認两个版本和用户可访问的资料范围。
2. 需要判断引用时再读取 references/evidence-rules.md。
3. 每个结论列出文档 ID、版本与证据片段位置。
4. 缺少来源就标记未确认；不要补造事实。

动手：把判断变成证据

  1. 在自己的练习目录创建一个 release-diff Skill，正文只保留任务方法，把详细引用规则移到 references。
  2. 设计四条触发用例：比较版本、解释流程、闲聊、缺少目标版本；写出期望的加载行为。
  3. 检查只有比较任务加载详细规则，缺少版本时先澄清；即使脚本被建议执行，也要经过既有工具授权。

验收：Skill 包路径可解析；正文引用的文件存在；四条用例各有预期；没有把脚本文件存在当成执行许可。

完成后再展开：参考解与检查思路

“比较 v1 与 v2”应激活；“什么是发布流程”可直接解释而不加载操作方法；闲聊不激活；缺少版本先补齐任务边界。记录加载的字节数或 token 估算，并测试正文修改后效果，不能只证明目录结构合法。

检索练习：不看上文作答

加载了 Skill 后，工具权限应当如何变化？

答案与原因（离线、无脚本也可阅读）

答案：保持原有约束。Skill 提供方法和上下文，权限仍由宿主与执行策略决定。

换个场景再判断

同名 Skill 在项目和用户目录各有一份，应该静默合并正文吗？

迁移题参考答案

不要假设通用合并规则。先核对所用宿主的查找与优先级约定，记录实际来源与版本；存在冲突时明确选用一份并测试触发，避免重复或相互矛盾的指令进入上下文。
