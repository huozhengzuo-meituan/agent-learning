08 · 可靠性与评估 · Lesson 0024

评分器、重复试验与回归判断

组合确定性检查与经过校准的模型评分，并用重复试验判断一次改动是否值得保留。

阅读与判断 15–20 分钟实验 20–40 分钟资料核对：2026-09-22

前置：第 0023 课的任务集；基本比例、数组聚合。

能力状态：通用工程机制；本文 TypeScript 是概念示意，未连接真实模型或生产存储。

本课服务于研发知识助手项目；页面备齐不代表已经掌握。以动手结果、解释和后续迁移作为学习证据。

先看能明确判定的事实

“答案很好”太模糊。把质量拆成证据支持、关键事实覆盖、越权、写入是否发生、耗时等维度。数据库是否新增两条重复任务可由程序检查；一段解释是否清楚可能需要人工或模型评分。不要让较好的文案分抵消未经批准的写入：本项目把安全边界设为硬门槛。

模型评分器也会被措辞、位置和被评文本中的指令影响。评分输入把候选回答当数据，规则与证据另放可信层；让评分器返回理由、证据位置和“不确定”。挑选一组人工已判定的正例、反例和边界例校准，版本变化后重新核对。LangSmith 的评估概念文档说明了不同 evaluator 和评估方式，适合用来设计这层分工。资料：Evaluation concepts。

重复跑同一道题，才看得到不稳定

每个任务运行多次，既报告所有 trial 的成功比例，也看一个任务是否每次都能通过。下例聚合三个任务、每题三次的结果。它计算的是这一小批试验的经验指标，不是对未来生产成功率的精确估计。

const trials = [
  [true, true, true],
  [true, false, true],
  [false, false, true]
];
const individual = trials.flat();
const successRate = individual.filter(Boolean).length / individual.length;
const anySuccess = trials.filter(t => t.some(Boolean)).length / trials.length;
const allSuccess = trials.filter(t => t.every(Boolean)).length / trials.length;
// successRate=6/9；至少一次成功=3/3；每次都成功=1/3。

“三次里至少一次成功”和“三次必须全部成功”描述不同需求。用户只尝试一次的产品，不能用 best-of-many 的漂亮分数替代单次可靠性。Anthropic 的 2026 年评估文章用 pass@k 与 pass^k 讨论这种差别；估计方法与试验独立性需要写清，不能混用名称。资料：Non-determinism in evals。

比较改动时保留失败分布

提示 A 与 B 使用同一题集、语料和工具版本，交错运行以减轻时间段差异。按任务配对查看从通过变失败和从失败变通过的题，不只看总平均。报告试验次数、样本大小、成本与延迟；小样本变化先当线索，增加重复或做置信区间分析，再决定是否发布。

一个可执行的课程门槛是：确定性安全检查全部通过；核心任务成功率不下降；新增能力达到事先定义的要求；成本和延迟仍在预算内。具体阈值要由你的应用需求制定，不能把本课练习分数当行业标准。评分器本身也要测试：参考正确答案要通过，明显错误答案应失败，合理的另一种解法不能无故扣分。

动手：让边界可观察

  1. 不运行代码，先手算上面三个指标，再核对。
  2. 设计一个“引用 ID 合法但结论错误”的反例，看看只检查 ID 的 grader 会不会误判。
  3. 模拟 A、B 各 9 次试验，总成功数相同，但 B 多了一次未批准写入；写出是否接受 B 及原因。
  4. 为模型评分器写 3 条明确规则，并给“不足以判断”一个合法返回值。

验收：算出 2/3、1、1/3；不因总成功数相同而接受越权版本；能把 grader 误判和 Agent 失败区分开。

完成后查看参考解

第一行三次成功，第二行两次，第三行一次，共 6/9。每题至少成功一次，所以 anySuccess=1；只有第一题全部成功，allSuccess=1/3。B 违反硬门槛，应拒绝并回看执行轨迹；这不能被其他任务的更好文案抵消。

评分规则示例：每个发布日期必须被给定原文直接支持；不得把计划写成完成；原文冲突或缺失时返回 unknown 并指出缺口。把原文“计划发布”与回答“已经发布”作为必测反例，防止评分器只数链接。

不看上文，检验一次

三次尝试中只成功一次，对“每次都成功”的判断是什么？

答案与理由（无脚本时也可查看）

答案：这个任务未能通过。题目要求每次都通过，这个任务不满足；至少成功一次是另一个较宽的指标。

换个情境，还能做对吗？

更新了评分模型后总分提高 10%，Agent 代码完全没改。可以声称 Agent 能力提升吗？

迁移题参考思路

不能。变化可能来自评分尺度漂移。对同一批已保存输出同时运行新旧评分器，与人工校准集比较；先确认评价标准一致，再重新评估 Agent 的真实变化。
