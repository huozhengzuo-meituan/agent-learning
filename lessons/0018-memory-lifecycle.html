06 · 知识与记忆 · Lesson 0018

记忆的写入、读取与失效

设计可追溯、可修正、可删除的记忆记录，避免旧信息和模型猜测变成永久事实。

阅读与判断 15–20 分钟实验 20–40 分钟资料核对：2026-09-22

前置：第 0013–0014 课；授权作用域与上下文选择。

能力状态：通用工程机制；本文 TypeScript 是概念示意，未连接真实模型或生产存储。

本课服务于研发知识助手项目；页面备齐不代表已经掌握。以动手结果、解释和后续迁移作为学习证据。

保存得久，不代表值得保存

用户说“这个项目暂时使用 Node 22”，Agent 若记成“用户永远只用 Node 22”，下一次处理另一个仓库就会误导。记忆的难点不是存 JSON，而是确定内容属于谁、适用于什么、证据在哪里、何时失效，以及当前请求是否应该读取。

LangChain 将线程内状态与跨线程记忆分开，还讨论同步写入和后台写入的取舍。本课用更窄的项目事实记录来练习这些机制。资料：Memory overview。后台提取可能减少用户等待，却可能在用户刚刚纠正信息后把旧版本再次写入，所以版本与删除标记仍不可省。

先提候选，再按政策落库

我们的示例应用采用明确政策：仅保存用户指定的长期偏好或已读回的项目事实；助手推测只放当前运行状态。它是课程项目的选择，不是所有产品的唯一规则。记忆必须保留 sourceEventId；派生摘要不能反过来伪装成用户原话。

type Memory = {
  id: string; tenantId: string; userId: string; projectId: string;
  text: string; sourceEventId: string; revision: number;
  state: "active" | "superseded" | "deleted";
  expiresAt: number | null;
};
type Scope = Pick<Memory, "tenantId" | "userId" | "projectId">;
function canRecall(m: Memory, scope: Scope, now: number): boolean {
  return m.state === "active" &&
    m.tenantId === scope.tenantId && m.userId === scope.userId &&
    m.projectId === scope.projectId &&
    (m.expiresAt === null || m.expiresAt > now);
}

生命周期比自动提取更重要

  1. 候选
    来源与作用域
  2. 验证
    是否值得保存
  3. 读取
    相关、有效、授权
  4. 修订或删除
    同步索引与缓存

用户把项目运行环境从 22 改为 24：用新记录替代旧记录，把旧版标记 superseded，不能让向量搜索同时返回两条矛盾事实且不注明版本。用户要求删除时，主存储、索引和派生缓存都要处理；保留必要的无内容墓碑可防止后台旧任务复活记录。生产中的具体保留政策应明确说明。

同一项目记忆也会过时：依赖版本可以短期有效并在使用前从仓库核对，沟通偏好可以较长期保存。记忆工具只是读写界面，不自动解决信任与隔离。Claude 的记忆工具文档展示了由应用管理存储的模式，可用于比较职责边界。资料：Memory tool。

动手：让边界可观察

  1. 构造项目 P 的一条 active 记忆，来源为“用户确认 Node 22”。另写一条助手猜测“用户喜欢所有新技术”。
  2. 让 active 记忆分别在同项目、别项目、到期时间之后被读取；解释候选猜测为何不应按本应用政策落库。
  3. 模拟用户修正为 Node 24，再模拟晚到的旧后台任务试图覆盖最新记录。

验收：只有同作用域且未到期的 active 记录进入候选上下文。覆盖操作比较 revision；旧任务不能覆盖新状态或复活已删除记录。

建议先独立完成；本课代码用于理解机制。实验可在工作区新建笔记或 TypeScript 文件，真实 API 与依赖准备见 实验说明。

完成后查看参考解

首次记录 revision=1；修正生成 revision=2，将旧信息标成 superseded。后台任务携带 expectedRevision=1 时，当前已为 2，写入应失败并重新读取。删除同样增加版本，再清理索引；后台任务重新读取时看到 deleted，终止写入。仅保存主表却不清理检索缓存，会造成“删了还记得”。

长期保留应有来源和用途。模型的推测既没有用户确认也没有环境读回证据，按本课政策不得成为长期事实。

答案与理由（无脚本时也可查看）

答案：校验版本拒绝复活。删除也属于需要版本保护的状态变化；晚到任务不能绕过墓碑或版本检查。

用户在新项目里采用了另一套代码风格。你怎样避免“个性化”变成跨项目干扰？

迁移题参考思路

将通用沟通偏好与项目规范分不同作用域，读取时优先当前明确指令和项目来源。不要将单次项目选择上升成全局偏好；必要时将旧记录失效或缩小范围。
