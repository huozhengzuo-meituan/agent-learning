04 · 执行控制 · LESSON 0010

让任务在正确的时候停止

为 Agent 定义明确的停止原因，并把步骤、时间和用量预算放进程序控制。

阅读与检查 15–20 分钟动手任务 30 分钟资料核对 2026-09-22

这一课的具体成果

设计一份停止策略，能区分“任务完成”和“因为预算不足而终止”。

前置知识：完成第 0009 课，理解循环每一步发生的模型与工具调用。

停止是业务状态的一部分

模型可能生成答案，也可能持续查询相似资料。应用要定义什么时候允许继续、什么时候必须停止。完成、缺少必要信息、等待用户、用户取消、预算耗尽和执行失败，都是不同的终态或暂停状态。把它们全部显示成“已完成”，会把控制逻辑变成虚假的成功承诺。

对于知识助手，成功可以要求答案具有可用证据；如果步骤上限到了而没有结论，应报告已找到的材料与未完成部分。循环停下本身不说明业务任务完成。这个区分在长任务里尤其重要，因为用户往往只看到最终一条状态消息。

限制要放在真正执行的边界

“最多查三次”写在提示里，是给模型的行为指导；执行器在第四次请求前拒绝继续，才是可验证的限制。步骤数、工具调用数与网络尝试次数并不一定相等：一轮可能有多个工具，网络调用也可能被自动重试。因此先给每种预算命名，再明确它数的是什么。

当前 AI SDK 的 stopWhen 与 isStepCount提供循环控制，但具体检查时点与默认值必须按版本核对。不能把框架的“步数”直接理解成你业务里的“已完成任务数”。我们用自己的状态字段先表达产品约束，之后再映射到框架。

预算检查也有时间差

完成一轮后才统计用量，可能已经超出预算。启动下一轮之前，需要检查剩余空间，并对单次输出、工具返回和重试次数设置界限。如果使用估计值，应清楚标记；价格、模型计量和隐藏的重试路径都可能使估算失真。严格费用上限需要更完整的预算预留与计费约束。

总超时信号应贯穿整个任务，单步也可能需要更短超时。只在 while 开头检查时钟，无法终止一个已经挂起的网络请求；取消信号必须传给支持它的底层操作。AI SDK settings列出 abortSignal 与 timeout 的边界，工具自身也需要遵守取消约定。

把过程放进 TypeScript

自定义预算判定片段；token 数为练习给定值，nextTokenAllowance 只在题目约定的上界模型中有效，不是实际费用保证。

type Budget = {
  modelCalls: number;
  maxModelCalls: number;
  usedTokens: number;
  maxTokens: number;
  deadlineAt: number;
};

function whyStop(
  b: Budget,
  now: number,
  nextTokenAllowance: number,
): "step-limit" | "time-limit" | "token-limit" | null {
  if (now >= b.deadlineAt) return "time-limit";
  if (b.modelCalls >= b.maxModelCalls) return "step-limit";
  if (b.usedTokens + nextTokenAllowance > b.maxTokens) {
    return "token-limit";
  }
  return null;
}

const reason = whyStop({
  modelCalls: 2, maxModelCalls: 4,
  usedTokens: 1_700, maxTokens: 2_000,
  deadlineAt: 30_000,
}, 10_000, 400); // token-limit

返回 token-limit 后，不再启动下一次调用，并记录未完成状态。实际系统需要分别记录预算预留和已用量，避免并发任务同时花掉同一份余额。本课先用单任务、单线程的数字例子建立概念。

动手：为三条轨迹写停止结果

  1. 轨迹 A：第一次查询得到明确证据并生成答案。轨迹 B：第四轮仍请求查询。轨迹 C：用户在第二轮取消。分别写停止原因与用户可见文本。
  2. 把预算例子的预留值从 400 改成 300，预测是否允许下一步；再把当前时间改成 30,000。
  3. 说明为什么每次重试也应消耗尝试次数和时间预算，而不能无限绕过循环步数。
验收条件

完成、上限、取消没有合并；边界值 now === deadlineAt 会停止；用量不足时不启动下一轮；明确估算预算不能当作已核实费用。

做过以后，再看参考答案

A 可以进入有证据的完成状态；B 应显示步骤上限并说明尚未得出完整结论；C 显示已取消。预留 300 在给定数字模型里刚好不超额，可以启动；时间等于 deadlineAt 时停止。重试虽然可能属于同一逻辑步骤，却仍消耗网络尝试、延迟与可能的费用。

停下来，从记忆里回答

循环因为步数上限退出，但尚未得到证据，应该如何报告？

答案与理由

应选“报告预算停止”，并说明已有结果和未完成部分，不能用成功文案掩盖缺口。

换个需求，还能用吗？

一个 Agent 在每轮并行启动五个工具，只限制“最多四轮”足够约束资源吗？

迁移题参考要点

不足够。它可能产生二十次工具执行，还可能包含网络重试。应分别约束工具总数、并发数、单次工具成本、总时间与用量；框架步数只是其中一个维度。
