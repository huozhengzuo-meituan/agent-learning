用新需求证明能力可以迁移

面对一个未做过的需求，独立选择架构、验证取舍并解释失败。

阅读 10–15 分钟 · 练习 20–40 分钟（综合项目另计）来源核对：2026-09-22应用侧 · TypeScript

本课交付：面对一个未做过的需求，独立选择架构、验证取舍并解释失败。

前置：0024 评分器、重复试验与回归判断、0026 测量并优化任务成本与延迟、0029 MCP 连接了什么，留下了什么、0032 何时值得引入多个 Agent、0034 Skills 与渐进式上下文加载、0037 后台 Agent 与持久任务生命周期、0039 完成研发知识助手综合项目

场景统一使用虚构文档与工单。代码注明示意时，需要接入你自己的项目上下文；本页不会发起模型调用。

先理解这个工程问题

先独立完成 任务书中的“跨版本 API 差异解释”：只找到一个版本时必须说明缺失，先写 5 条验收再实现。本课再提供一个独立加测，以下评分仅用于这份新作业，与综合项目评分不同。熟悉同一个项目会产生熟练错觉，因此换一个目标：为虚构的开源项目维护者准备“本周 issue 复盘草稿”，整合重复问题、识别证据冲突、给出待跟进项；不自动关闭 issue 或发消息。你只能复用基础设施，不能复制上一课的提示与评分用例后改个名字。

先写一页设计：用户需要什么结果，输入信任级别是什么，工具能读写什么，何时需要动态探索，成功怎样判断。比较确定性程序、单次模型调用与单 Agent 三个基线；只有独立分支真的带来收益才考虑多 Agent。需要跨会话运行时，再比较自己维护运行时与托管服务。

以 MCP 的职责边界解释连接层，以 2026-09 的 Agents API 公测介绍讨论托管选项；公测能力只能作为候选，不能忽略账号、地域、隐私和版本限制。文章介绍不是你的性能测试结果。

评分关注迁移能力：需求与范围 20 分、最小合理架构 20 分、边界和失败处理 25 分、可复现评估 25 分、口头取舍 10 分。具体失败题：同一 issue 在两个来源出现，时间戳不同，Agent 把两条都当成新问题并重复计数。你需找出身份去重与证据冲突处理的位置，而非单纯增加提示长度。

读一段代码或执行轨迹

先预测输出或指出边界，再对照注释。以下为课程教学片段；基础机制的可运行实验见 实验说明。本课特定集成需按练习自行实现，未声称已运行。

type Issue = { source: string; project: string; number: number; updatedAt: string };
function identity(issue: Issue): string {
  return `${issue.project}:${issue.number}`;
}
const a: Issue = { source: "cache", project: "atlas", number: 42,
  updatedAt: "2026-09-20T08:00:00Z" };
const b: Issue = { source: "live", project: "atlas", number: 42,
  updatedAt: "2026-09-21T08:00:00Z" };
console.log(identity(a) === identity(b)); // true：来源不同不代表两个 issue
// 冲突时保留来源和版本；更新时间较新也不自动证明其内容权威。

动手：把判断变成证据

  1. 限时 45 分钟独立写需求、边界和两种方案对照；先写验收，后设计实现。
  2. 用 90 分钟实现最小原型并准备 8 条新任务，至少包含重复记录、冲突证据、工具超时和恶意正文。
  3. 做 10 分钟答辩：说明为何选此方案、最贵步骤、何时升级架构、一次失败的证据，以及未完成验证。

验收：新任务不泄漏进训练式提示调优过程；能用运行结果解释取舍；对未支持的写入明确拒绝；他人可复现一条失败。

完成后再展开：参考解与检查思路

可以先使用固定只读工具加单 Agent；标准化 issue 身份与去重交给程序，含糊的归类和补充检索留给模型。评分用结构正确、覆盖关键证据、避免重复与明确冲突的组合，不以文字像参考答案作为唯一标准。

迁移题参考答案

先说明目标与约束，例如租户数据访问及可导出运行证据。再比较托管减少的运维工作与仍由应用负责的授权、幂等和评估。最后提出一个相同任务集上的小型对照实验，用成功率、恢复、成本与迁移能力决定，而不是凭新旧选边。
